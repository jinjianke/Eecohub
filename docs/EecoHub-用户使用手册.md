# EecoHub 静态网站部署平台使用手册

> 文档版本：1.0  
> 更新日期：2026年7月29日  
> 平台入口：[https://eecohub.top](https://eecohub.top)

---

## 1. 平台简介

EecoHub 是一个面向静态网页的在线发布工具。

购买服务后，你会获得一张部署卡密。打开 EecoHub，输入卡密并上传网站文件，系统会自动完成文件检查、云端发布，并生成一个可以在电脑和手机浏览器中打开的 HTTPS 公网网址。

整个过程不需要你自己购买服务器、安装运行环境、配置 Nginx、申请 SSL 证书或绑定域名。

### 1.1 核心功能

- 支持上传单个 `.html` 或 `.htm` 文件；
- 支持上传完整的 `.zip` 静态网站压缩包；
- 支持 HTML、CSS、JavaScript、图片、字体、音频等静态资源；
- 自动生成 HTTPS 公网访问网址；
- 同一卡密可以重新上传并覆盖更新网站；
- 覆盖更新后，原来的访问网址保持不变；
- 卡密在首次成功发布后激活；
- 激活后有效期为 365 天；
- 页面会显示发布次数和到期日期。

### 1.2 适用项目

EecoHub 适合发布以下类型的纯静态项目：

- HTML/CSS/JavaScript 课程作业；
- 个人主页或电子简历；
- 个人作品集；
- 前端练习项目；
- 产品介绍页面；
- 活动介绍页面；
- 表白、祝福或纪念网页；
- AI 生成的静态网页；
- 不依赖服务器后端的展示页面。

### 1.3 不支持的项目

EecoHub 不是后端服务器，不能直接运行以下内容：

- PHP；
- Python、Flask、Django；
- Node.js、Express、Next.js 服务端程序；
- Java、JSP、Spring Boot；
- ASP、ASP.NET；
- MySQL、SQLite、Redis 等服务器数据库；
- 需要在服务器执行命令或安装依赖的项目；
- 需要服务器保存用户账号、订单或表单数据的系统；
- `.exe`、`.dll`、`.bat`、`.cmd`、`.sh`、`.ps1` 等可执行文件或脚本；
- ZIP 中再次包含 ZIP、RAR、7Z 等嵌套压缩包。

> 如果你的项目中有 `package.json`，不一定代表不能部署。若项目已经通过 Vite、Vue、React 等工具完成构建，可以尝试上传构建生成的静态目录，例如 `dist` 目录中的内容，而不是上传完整源代码项目。

## 2. 使用前需要准备什么

开始部署前，请准备：

1. 卖家发送给你的 EecoHub 卡密；
2. 一个可以正常打开的 HTML 文件，或者一个完整静态网站 ZIP；
3. Chrome、Edge、Safari 等现代浏览器；
4. 稳定的网络连接。

卡密通常类似：

```text
EH-XXXX-XXXX-XXXX
```

请完整复制卡密，不要遗漏字符，也不要在卡密中加入多余空格。

### 2.1 推荐浏览器

推荐使用最新版：

- Microsoft Edge；
- Google Chrome；
- Safari；
- Firefox。

如果微信或咸鱼内置浏览器上传异常，建议点击右上角菜单，选择“在浏览器中打开”，再使用系统浏览器完成上传。

## 3. 第一次发布网站

### 第一步：打开 EecoHub

在浏览器中访问：

[https://eecohub.top](https://eecohub.top)

确认地址栏中显示的是 `https://eecohub.top`，不要在来历不明的仿冒页面中输入卡密。

### 第二步：输入卡密

1. 找到“输入卡密”区域；
2. 粘贴卖家发送的完整卡密；
3. 点击 **“验证并继续”**；
4. 验证成功后，页面会进入文件上传步骤。

如果提示卡密错误，请检查：

- 是否复制了完整卡密；
- 卡密开头和结尾是否多了空格；
- 字母和数字是否输入错误；
- 是否误把订单号或买家 ID 当成卡密；
- 卡密是否已停用或到期。

### 第三步：选择网站文件

验证卡密后，可通过以下任一方式选择文件：

- 点击上传区域，在文件选择器中选择文件；
- 将文件直接拖放到上传区域。

当前支持：

```text
.html
.htm
.zip
```

上传前页面会显示文件名和文件大小。请确认选择的是正确版本，再继续发布。

### 第四步：发布到云端

1. 点击 **“发布到云端”**；
2. 等待系统检查和上传文件；
3. 发布期间不要关闭或刷新页面；
4. 一般需要约 10～60 秒，文件较多或网络较慢时可能需要更长时间；
5. 页面出现“网站发布成功”后，即表示部署完成。

> 不要连续重复点击发布按钮。如果长时间没有结果，请先等待，之后再根据错误提示处理。

### 第五步：获取网址

发布成功后，页面会显示：

- 网站公网网址；
- 本次上传的文件数量；
- 累计发布次数；
- 卡密有效期截止日期。

你可以：

- 点击 **“复制”** 复制网址；
- 点击 **“打开网站”** 检查最终效果；
- 将网址发送给其他人访问；
- 保存卡密和网址，以便以后更新网站。

生成的网址通常类似：

```text
https://eeco-xxxxxxxx.rth1.xyz
```

实际网址以发布成功页面显示的结果为准。

## 4. 单个 HTML 文件的制作与上传

如果你的网页只有一个 HTML 文件，可以直接上传，不需要制作 ZIP。

### 4.1 文件要求

- 扩展名必须是 `.html` 或 `.htm`；
- 文件大小不能超过 10MB；
- HTML 文件不能是空文件；
- 推荐使用 UTF-8 编码保存中文内容。

例如：

```text
我的网页.html
```

上传后，系统会自动把它作为网站首页发布。

### 4.2 适合直接上传单个 HTML 的情况

- CSS 已写在 `<style>` 标签中；
- JavaScript 已写在 `<script>` 标签中；
- 没有单独的本地图片、CSS 或 JS 文件；
- 图片使用的是可靠的网络地址；
- 网页本身可以独立运行。

### 4.3 单个 HTML 中使用本地资源

如果 HTML 还需要同一电脑里的图片、CSS 或 JS，例如：

```html
<link rel="stylesheet" href="css/style.css">
<script src="js/main.js"></script>
<img src="images/logo.png" alt="Logo">
```

就不能只上传 HTML 文件。你需要把 HTML 和所有资源一起整理后压缩为 ZIP，具体方法见下一章。

## 5. ZIP 静态网站的制作与上传

ZIP 适合包含多个页面、CSS、JavaScript、图片、字体或其他静态资源的网站。

### 5.1 标准目录结构

推荐结构：

```text
index.html
css/
  style.css
js/
  main.js
images/
  logo.png
  banner.jpg
fonts/
  example.woff2
pages/
  about.html
```

最重要的要求是：网站入口文件必须叫：

```text
index.html
```

### 5.2 正确的压缩方式

假设网站文件夹为：

```text
my-website/
  index.html
  css/
  js/
  images/
```

推荐做法：

1. 打开 `my-website` 文件夹；
2. 选中里面的 `index.html`、`css`、`js`、`images` 等内容；
3. 右键选择“压缩为 ZIP 文件”；
4. 上传生成的 ZIP。

推荐的 ZIP 内部结构：

```text
index.html
css/style.css
js/main.js
images/logo.png
```

以下这种只有一个外层文件夹的结构通常也可以自动识别：

```text
my-website/index.html
my-website/css/style.css
my-website/js/main.js
```

但不要嵌套多层无关文件夹，例如：

```text
作业最终版/新建文件夹/网页/完成版/index.html
```

为减少路径错误，建议直接压缩网站文件本身。

### 5.3 Windows 制作 ZIP

1. 打开网站文件夹；
2. 选中网站所需的全部文件；
3. 右键选择 **“压缩到 ZIP 文件”** 或 **“发送到 → 压缩（zipped）文件夹”**；
4. 给压缩包起一个简单名称，例如 `website.zip`；
5. 打开 ZIP 检查是否能看到 `index.html`。

### 5.4 macOS 制作 ZIP

1. 打开网站文件夹；
2. 选中需要发布的全部内容；
3. 右键选择 **“压缩”**；
4. 检查生成的 ZIP 是否包含 `index.html`；
5. 上传该 ZIP 文件。

### 5.5 ZIP 大小和文件数量限制

当前限制如下：

| 项目 | 限制 |
|---|---:|
| 上传的 HTML 或 ZIP | 最大 20MB |
| ZIP 解压后的总大小 | 最大 50MB |
| ZIP 内文件数量 | 最多 1000 个 |
| ZIP 内单个文件 | 最大 10MB |
| 网站入口 | 根目录必须有 `index.html` |

如果超过限制，请删除不需要的文件，压缩图片、音频或视频，或者联系卖家确认其他处理方式。

### 5.6 不要放进 ZIP 的内容

发布时通常不需要包含：

```text
node_modules/
.git/
.vscode/
.idea/
src/（如果项目已经构建）
项目设计稿
PSD源文件
无关视频
备份压缩包
数据库文件
```

这些文件会明显增加体积，并可能导致上传失败。

## 6. HTML、CSS 和 JavaScript 路径规则

网站发布后是在互联网服务器上运行，不再读取你电脑中的文件。因此，资源路径必须正确。

### 6.1 推荐使用相对路径

正确示例：

```html
<link rel="stylesheet" href="css/style.css">
<script src="js/main.js"></script>
<img src="images/logo.png" alt="Logo">
<a href="pages/about.html">关于我们</a>
```

也可以使用：

```html
<link rel="stylesheet" href="./css/style.css">
<img src="./images/logo.png" alt="Logo">
```

### 6.2 不要使用电脑本地绝对路径

错误示例：

```html
<img src="C:\Users\Admin\Desktop\website\logo.png">
<link rel="stylesheet" href="D:\Project\css\style.css">
```

下面这种浏览器本地文件地址也不能用于公网网站：

```text
file:///C:/Users/Admin/Desktop/image.png
```

这些地址只能在你的电脑上使用，其他人无法访问。

### 6.3 注意文件名大小写

云端服务器通常严格区分大小写：

```text
logo.png
Logo.png
LOGO.PNG
```

可能会被当作三个不同文件。

如果实际文件名是：

```text
images/Logo.png
```

HTML 中也必须写成：

```html
<img src="images/Logo.png" alt="Logo">
```

不要写成 `images/logo.png`。

### 6.4 文件名建议

推荐：

```text
index.html
about.html
style.css
main.js
logo.png
banner-01.jpg
```

尽量避免：

- 文件名中包含空格；
- 特殊符号；
- 过长的中文文件名；
- 同一目录中使用仅大小写不同的文件名。

中文文件名通常可以使用，但为了提高兼容性，建议使用小写英文字母、数字、短横线和下划线。

## 7. Vue、React、Vite 等前端项目如何上传

EecoHub 不能直接运行需要 `npm run dev` 的源代码项目，但可以部署已经构建完成的静态文件。

### 7.1 Vite 项目

通常先在项目目录执行：

```bash
npm install
npm run build
```

构建完成后会生成：

```text
dist/
```

确认 `dist` 中包含：

```text
dist/index.html
dist/assets/...
```

然后：

1. 打开 `dist` 文件夹；
2. 选中 `dist` 里面的全部内容；
3. 压缩为 ZIP；
4. 上传 ZIP。

不要直接把整个项目和 `node_modules` 一起上传。

### 7.2 React 项目

不同工具生成的静态目录可能是：

```text
dist/
```

或者：

```text
build/
```

请上传构建输出目录中的内容，并确保根目录有 `index.html`。

### 7.3 Vue 项目

一般执行：

```bash
npm install
npm run build
```

然后上传 `dist` 目录内的静态文件。

### 7.4 单页应用路由注意事项

如果项目使用 Vue Router、React Router 等前端路由：

- 使用 Hash 路由（网址中带 `#`）通常兼容性更好；
- History 路由在直接打开子页面时可能出现 404；
- 发布前建议确认项目可以在纯静态托管环境运行；
- 如果刷新子页面出现 404，可改用 Hash 路由后重新构建。

示例 Hash 路由网址：

```text
https://示例网址/#/about
```

## 8. 更新已经发布的网站

同一张卡密可以用于覆盖更新它已经绑定的网站。

### 8.1 更新步骤

1. 打开 [https://eecohub.top](https://eecohub.top)；
2. 输入第一次发布时使用的同一卡密；
3. 验证成功后，页面会显示当前网站网址；
4. 选择新的 HTML 或 ZIP 文件；
5. 点击 **“发布到云端”**；
6. 发布成功后打开原网址检查内容。

### 8.2 更新后的结果

- 原网址保持不变；
- 新文件会覆盖网站原有内容；
- 发布次数会增加；
- 有效期不会因重新上传而重新计算；
- 第一次成功发布后生成的到期日期保持不变，除非卖家为卡密办理续期。

### 8.3 更新前的重要提醒

每次重新上传都应当提供一个完整、可独立运行的网站包。

不要只上传一个修改过的 CSS 文件或一张新图片，因为系统接受的是完整网站发布包，而不是单文件增量补丁。

例如原网站包含：

```text
index.html
css/style.css
js/main.js
images/logo.png
```

更新时仍应把这些完整文件一起放入 ZIP 上传。

### 8.4 更新后仍显示旧内容

通常是浏览器缓存导致，可以尝试：

- Windows：按 `Ctrl + F5` 强制刷新；
- macOS：按 `Command + Shift + R`；
- 手机：关闭页面后重新打开；
- 使用浏览器无痕模式访问；
- 清除该网站的浏览器缓存；
- 等待几十秒后再次打开。

也可以在网址末尾临时加入查询参数测试：

```text
https://你的网站网址/?v=2
```

## 9. 卡密规则

### 9.1 首次激活

- 新卡密验证成功并不等于已经激活；
- 卡密在第一次网站发布成功后才正式激活；
- 第一次发布失败通常不会开始计算 365 天有效期；
- 首次成功发布时，卡密会绑定对应的网站网址。

### 9.2 有效期

- 卡密激活后有效期为 365 天；
- 页面会显示具体到期日期；
- 重新上传不会重置有效期；
- 到期后将不能继续使用该卡密发布或更新；
- 如需继续使用，请在到期前联系卖家咨询续期。

### 9.3 卡密与网址

- 一张卡密对应一个固定网站；
- 使用同一卡密更新时，网站网址保持不变；
- 不要把卡密公开发布或发送给无关人员；
- 获得卡密的人可能可以覆盖你的网站内容；
- 公开分享网站网址即可，不要同时分享卡密。

### 9.4 妥善保存

建议把以下信息保存在安全位置：

```text
订单号：
买家 ID：
EecoHub 卡密：
网站网址：
首次发布日期：
到期日期：
```

如果丢失卡密，请使用原购买账号联系卖家，并提供订单信息和买家 ID。是否能够找回或补发，以卖家核验结果为准。

## 10. 内容安全限制

为了防止钓鱼、诈骗、恶意跳转和危险程序，平台会检查上传内容。

请勿上传：

- 违法违规内容；
- 诈骗、仿冒登录、钓鱼页面；
- 收集账号密码的页面；
- 侵犯他人著作权、商标权、肖像权或隐私权的内容；
- 赌博、色情、恶意营销或其他违规内容；
- 病毒、木马、后门或可执行程序；
- 自动跳转到其他网站的恶意代码；
- 恶意弹窗；
- 冒充银行、支付平台、社交平台或政府机构的页面。

### 10.1 可能被安全检查拦截的代码

下列功能可能触发安全限制：

- 密码输入框；
- 自动刷新或自动跳转；
- `iframe` 嵌入其他网页；
- 向外部网址提交表单；
- 使用 JavaScript 修改 `window.location`；
- 使用 `location.assign()` 或 `location.replace()`；
- 使用 `window.open()` 自动弹窗；
- `javascript:` 类型的链接。

如果你的正规项目确实需要类似功能，请先联系卖家说明用途，不要尝试绕过平台检查。

## 11. 常见问题与解决方法

### 11.1 提示“卡密不正确”

可能原因：

- 卡密复制不完整；
- 输入了订单号而不是卡密；
- 卡密前后带有空格或换行；
- 字符输入错误；
- 卡密并非由当前卖家发放。

解决方法：重新复制卖家发送的完整卡密。如果仍然失败，把订单信息和错误提示截图发给卖家。不要在公开评价或公开聊天区域展示完整卡密。

### 11.2 提示“卡密已停用”

该卡密当前被暂停使用。请使用购买时的账号联系卖家核实订单和使用情况。

### 11.3 提示“卡密已过期”

卡密已超过有效期，不能继续发布。请联系卖家咨询续期，不要重复购买前先确认原网址和续期方式。

### 11.4 提示“请选择 HTML 或 ZIP 文件”

当前仅支持：

```text
.html
.htm
.zip
```

RAR、7Z、文件夹或其他格式不能直接上传。请把完整静态网站压缩成 ZIP。

### 11.5 提示“文件不能超过 20MB”

请减少文件体积，例如：

- 压缩 JPG、PNG、WebP 图片；
- 删除无用图片和备份文件；
- 删除 `node_modules`；
- 删除设计源文件；
- 不要加入大型视频；
- 删除 ZIP 内嵌套的压缩包。

### 11.6 提示“网站根目录必须包含 index.html”

ZIP 中没有找到入口文件。请检查：

- 文件名是否确实为 `index.html`；
- 是否误写成 `index.htm.txt`；
- 是否只压缩了空文件夹；
- 是否存在多层无关目录；
- 大小写和文件扩展名是否正确。

打开 ZIP 后，最好能直接看到：

```text
index.html
```

### 11.7 提示“ZIP 文件无法读取”

可能是压缩包损坏或实际格式不是 ZIP。请：

1. 在电脑上尝试正常打开 ZIP；
2. 解压原文件；
3. 重新使用系统自带功能压缩为 ZIP；
4. 不要只是把 `.rar` 后缀改成 `.zip`；
5. 重新上传。

### 11.8 提示“不支持文件类型”

ZIP 中可能包含后端文件、可执行文件、脚本程序或嵌套压缩包。删除错误提示中指出的文件，再重新压缩上传。

### 11.9 提示包含密码框、跳转、iframe、外部表单或弹窗

这是平台安全检查触发。请检查并删除对应代码。若项目用途正规但必须使用该功能，请先与卖家沟通确认支持范围。

### 11.10 发布成功，但页面是空白

依次检查：

1. `index.html` 是否有实际内容；
2. 按 `F12` 打开浏览器开发者工具，查看 Console 是否报错；
3. CSS 和 JS 路径是否正确；
4. 文件名大小写是否一致；
5. 是否上传了构建后的 `dist`，而不是项目源代码；
6. JavaScript 是否依赖本地开发服务器；
7. 项目是否使用了不适合静态托管的绝对路径。

### 11.11 发布成功，但 CSS 没有生效

检查 HTML 中的路径：

```html
<link rel="stylesheet" href="css/style.css">
```

并确认 ZIP 中确实存在：

```text
css/style.css
```

还要确认 `style.css` 与 `Style.css` 的大小写一致。

### 11.12 发布成功，但图片不显示

检查：

- 图片是否已经放入 ZIP；
- HTML 中是否使用相对路径；
- 图片文件名和扩展名是否正确；
- 大小写是否一致；
- 是否误用了电脑本地路径；
- 图片是否损坏；
- 网络图片地址是否允许外部访问。

### 11.13 JavaScript 在本地正常，发布后失效

可能原因：

- JS 文件路径错误；
- 代码依赖本地开发服务器；
- API 服务不允许跨域访问；
- 页面通过 HTTPS 打开，但代码请求的是 HTTP 接口；
- 使用了 Node.js 专用模块，无法直接在浏览器中运行；
- 使用了自动跳转或弹窗代码，被安全检查拦截；
- 构建时资源基础路径配置错误。

### 11.14 浏览器提示 Mixed Content

EecoHub 网站使用 HTTPS。如果页面请求 HTTP 资源，现代浏览器可能阻止加载。

错误示例：

```text
http://example.com/api
```

建议改为：

```text
https://example.com/api
```

前提是对方接口本身支持 HTTPS。

### 11.15 调用第三方 API 失败

静态网站可以在浏览器中请求第三方接口，但接口必须允许浏览器跨域访问，并支持 HTTPS。

请注意：

- CORS 是否开放由第三方接口决定；
- 不要在前端代码中放置私密 API Key、数据库密码或服务器密钥；
- 前端 JavaScript 中的任何内容都可能被访问者查看；
- 需要隐藏密钥的功能必须使用独立后端，EecoHub 静态托管无法代替安全后端。

### 11.16 点击链接后出现 404

检查链接目标文件是否存在，并确认大小写一致。

如果是 React Router 或 Vue Router 项目刷新子页面出现 404，建议改为 Hash 路由，再重新构建上传。

### 11.17 发布一直停留在“正在发布”

请：

1. 至少等待 1～3 分钟；
2. 不要连续点击发布；
3. 检查本地网络是否中断；
4. 刷新 EecoHub 页面；
5. 重新输入同一卡密；
6. 再次上传完整文件；
7. 仍然失败时，将错误截图、文件大小和发生时间发送给卖家。

### 11.18 其他人打不开，但自己可以打开

请确认：

- 分享的是发布成功页面生成的 `https://` 网址；
- 没有误把本地地址 `localhost` 发给别人；
- 没有分享 `file:///` 地址；
- 复制网址时没有遗漏字符；
- 对方网络是否正常；
- 换用其他浏览器或移动网络测试。
